Carnage PCAP Analysis

Network Forensics Incident Response Report · Wireshark · TryHackMe Carnage

1. Executive Summary

The investigation found that the victim workstation was compromised after malicious content was downloaded and executed. Network evidence showed the workstation communicating with multiple malicious domains, post-infection infrastructure, and Cobalt Strike command-and-control servers. The activity included malicious file delivery, follow-on C2 communication, public-IP discovery and SMTP activity. The affected workstation should be isolated, the identified indicators blocked, and the wider environment searched for the same infrastructure and files.

4. Investigation & Analysis

Wireshark filtering began with http.request. Repeated outbound traffic from the victim was reviewed for suspicious downloads. The archive was identified through the HTTP GET request and reconstructed using Wireshark's HTTP object export. The archive was inspected locally without interacting with the malicious infrastructure.

HTTP response headers were then examined to identify server software. TLS Client Hello and certificate traffic were correlated by TCP stream to identify domains and certificate issuers. HTTP POST traffic was investigated to identify repeated post-infection communication and candidate C2 infrastructure. VirusTotal Community data was used to corroborate the Cobalt Strike association.

6. Containment & Recommendations

Next hour

  1. Isolate the affected workstation while preserving evidence.
  2. Block identified malicious IPs and domains at DNS, firewall and proxy controls.
  3. Search EDR, DNS, proxy, firewall and email logs for the IOCs and malicious filename.
  4. Identify other recipients of the same malicious email or archive.
  5. Reset credentials and revoke sessions if endpoint evidence indicates credential exposure.

Longer term

  • Strengthen email attachment and macro controls.
  • Use application control to prevent Office applications from launching scripting engines.
  • Improve endpoint telemetry for process creation and outbound network connections.
  • Maintain central IOC monitoring and threat-hunting rules.

Concrete detection idea

Alert when WINWORD.EXE or EXCEL.EXE launches powershell.exe, cmd.exe, wscript.exe or mshta.exe and the child process makes an outbound connection. A second rule should alert on repeated outbound HTTP POST requests from an internal workstation to a previously unseen external domain/IP with unusual or encoded-looking URI/body data.
